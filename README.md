# ARIS Cloud

Чат с Gemini, Grok, OpenRouter и любым API, совместимым с OpenAI Chat Completions.
Сайт статичный, состояние живёт в Supabase: вход по почте и паролю, ключи, история чатов и вложения
доступны с любого устройства. Локальный `server.mjs` больше не нужен.

```
Браузер ──► Supabase (Auth · Postgres · Storage)   аккаунт, чаты, ключи, файлы
   └──────► API провайдера напрямую                запросы к моделям
```

## 1. Проект в Supabase (бесплатный тариф)

1. supabase.com → **New project**. Запомните пароль базы, регион берите ближе к себе.
2. **SQL Editor** → вставьте содержимое `supabase/schema.sql` → **Run**.
   Создадутся таблицы `profiles`, `chats`, приватный бакет `attachments` и политики RLS.
3. **Authentication → Providers → Email**: включён по умолчанию.
   Для быстрого старта можно выключить `Confirm email`, тогда вход сразу после регистрации.
4. **Authentication → URL Configuration**: в `Site URL` и `Redirect URLs` добавьте адрес сайта
   (например `https://aris.vercel.app`) и `http://localhost:5173` для локальной разработки.
   Без этого не сработают письма подтверждения и сброс пароля.
5. **Project Settings → API**: скопируйте `Project URL` и ключ `anon public`.

## 2. Ключи проекта в коде

`src/config.js`:

```js
export const SUPABASE_URL = window.ARIS_SUPABASE_URL || 'https://xxxxxxxx.supabase.co';
export const SUPABASE_ANON_KEY = window.ARIS_SUPABASE_ANON_KEY || 'eyJhbGciOi...';
```

`anon`-ключ публичный по замыслу Supabase: он лишь позволяет обратиться к API, а доступ к строкам
режет RLS. `service_role` в браузер класть нельзя никогда.

## 3. Публикация

Залейте папку в репозиторий GitHub, затем любой из вариантов:

- **Vercel**: Import Project → Framework `Other` → Build Command пустой, Output Directory `.` → Deploy.
- **Netlify**: Add new site → репозиторий → Publish directory `.` (готовый `netlify.toml` уже лежит рядом).
- **GitHub Pages**: Settings → Pages → Deploy from branch, `main` / `root`. Сайт откроется по адресу
  вида `https://user.github.io/aris/`, все пути в проекте относительные и это переживут.

Локально: `npm run dev` (статичный сервер на `http://localhost:5173`). Двойной клик по `index.html`
не подойдёт: модулям нужен `http`.

## 4. Как это работает

- **Вход.** Почта и пароль через Supabase Auth. Сессия хранится в браузере и продлевается сама,
  вход нужен один раз на устройство. Есть ссылка «Забыли пароль»: письмо возвращает на сайт с
  `#type=recovery`, и ARIS сразу просит новый пароль.
- **Подключения.** Провайдеры, модели и ключи лежат в `profiles.providers` вашей строки. При первом
  входе то, что осталось в localStorage старой версии, автоматически переносится в облако.
- **Запросы к моделям.** Идут из браузера напрямую: Gemini, OpenRouter и совместимые endpoint'ы
  принимают такие запросы. Цепочка прежняя: ключи по очереди, потом следующий провайдер, 45 секунд
  на попытку. Если провайдер не отдаёт CORS-заголовки, попытка падает с понятным сообщением
  «провайдер не разрешает обращения со страницы» — такому провайдеру нужен свой прокси
  (например Supabase Edge Function), см. раздел 6.
- **История.** Каждый чат — строка в `chats` (`messages` в jsonb). Сохранение отложенное, пачкой раз
  в ~0,6 секунды; при обрыве сети повтор через 5 секунд, а копия остаётся в localStorage.
- **Вложения.** До 4 файлов на сообщение, до 8 МБ каждый, картинки и текстовые форматы. Файл
  улетает в приватный бакет по пути `<user_id>/<uuid>`, в чате показывается по подписанной ссылке
  на час. Перед отправкой модели содержимое скачивается обратно: картинки как base64, текст как
  текст. Удаление чата удаляет и его файлы.

## 5. Что важно знать про безопасность

- Ключи провайдеров хранятся в базе в открытом виде и видны только вашей строке через RLS. Это
  нормально для личного аккаунта, но любой, кто получит вашу сессию или пароль, получит и ключи.
  Ставьте на аккаунт длинный пароль и включите подтверждение почты.
- Ключ уходит только на адрес своего провайдера, в логи и в чужие запросы не попадает; в текстах
  ошибок ключи маскируются.
- Свой провайдер принимается только по HTTPS без параметров и пароля в URL.

## 6. Если провайдер блокирует браузер (CORS)

Заведите Supabase Edge Function-прокси и подключите его как «Свой провайдер» с базовым URL
`https://<project>.functions.supabase.co/proxy/v1`. Функция должна пробрасывать тело запроса и
заголовок `Authorization` на реальный API и отдавать `Access-Control-Allow-Origin` с адресом сайта.

## 7. Лимиты бесплатного тарифа Supabase

500 МБ базы, 1 ГБ файлов, 50 000 активных пользователей в месяц. Проект без обращений
приостанавливается примерно через неделю простоя и поднимается из панели. Для личного чата этого
хватает с большим запасом; тяжёлые вложения удаляйте вместе с чатами.
